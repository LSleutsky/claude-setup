# React Router (framework mode)

The repo's existing way of doing each of these wins; these apply where it has none. They assume React Router 8 or newer. Check `package.json` first; on an older major use that version's API and say so. `@react-router/dev` means framework mode and every rule below applies; plain `react-router` is data mode (`createBrowserRouter` carries loaders and actions) or declarative mode (matching and navigation only), where the route module exports do not exist.

- Routes are declared in `app/routes.ts` with `route`, `index`, `layout`, and `prefix`. File-system routes (`@react-router/fs-routes`) only where the repo already uses them.
- Route loaders own data. `loader` runs on the server and is removed from the client bundle; `clientLoader` runs in the browser. When the client must load before first render, `clientLoader.hydrate = true as const` with a `HydrateFallback`. The component reads `loaderData` from `Route.ComponentProps`. A component that fetches on mount is a bug.
- Mutations go through `<Form method="post">` to the route `action`, or `useFetcher` when the URL must not change. Loaders revalidate after an action; never refetch by hand. Every `action` and `loader` validates `formData`, params, and search with the repo's validator.
- Expected failures `throw data(body, { status })` to the nearest `ErrorBoundary`, which separates them from bugs with `isRouteErrorResponse`. Redirects return `redirect()`. A route you add that loads data exports an `ErrorBoundary`.
- Pending state comes from `useNavigation().state` for navigations, `fetcher.state` for fetchers, and `NavLink`'s `isPending`. Never a loading flag in `useState` for a navigation.
- Types come from `import type { Route } from "./+types/<route>"`. `.react-router/types/` is generated by `react-router typegen`, gitignored, listed in tsconfig `rootDirs`, and never edited or hand-fixed to satisfy a type error.
- Navigation uses `<Link to>` and `href("/products/:id", { id })`. Never a string-built path.
- `react-router.config.ts` (`Config` from `@react-router/dev/config`) decides rendering: `ssr: false` without `prerender` is an SPA, `prerender` builds static HTML. The plan says which, and why.
- `middleware` and `clientMiddleware` are route exports. The `context` they share with loaders and actions is a `RouterContextProvider` keyed by `createContext`. Authorization is enforced on the server, never only in the browser.
- `.server` modules are excluded from the client bundle and `.client` modules from the server bundle. Secrets are read only in `.server` modules and `loader` or `action`, never in a component or `clientLoader`.
- `root.tsx` renders the document. `entry.client.tsx` and `entry.server.tsx` are optional; add one only when the task needs it.
